# Спецификация: Исправление контрастности текста в блоках трассировки Django Admin

**Дата:** 2026-09-28 03:38:50 MSK  
**Ветка:** `bugfix/admin-text-contrast`  
**Тип:** `bugfix`  
**Идентификатор задачи:** `admin-text-contrast`  

---

## 1. Постановка проблемы

На странице просмотра трассировки пайплайна сообщений в Django Admin (`/admin/api/messageprocessingtrace/<id>/change/`) текст внутри блоков с содержимым сообщений (например, блок WhatsApp сообщения `<div class="p-4 rounded-lg bg-white dark:bg-gray-900 border border-gray-200 dark:border-gray-800 text-sm text-gray-800 dark:text-gray-200 font-sans whitespace-pre-wrap leading-relaxed shadow-sm">`), а также в блоках контекста истории сообщений, данных Bitrix24 и извлеченных фактов AI отображается серым («около серый») цветом на белом фоне.

### Причина дефекта:
1. Тема панели управления построена на `django-unfold`.
2. Предкомпилированный CSS-бандл Unfold (`/static/unfold/css/styles.css`) использует семантическую цветовую палитру `base` и `font` (`bg-base-50`, `bg-base-900`, `text-font-default-light`, `text-font-important-light`, `border-base-200`), в то время как стандартные утилитарные классы Tailwind (`text-gray-800`, `dark:text-gray-200`, `border-gray-200`, `dark:bg-gray-900`, `text-gray-600`) отсутствуют в скомпилированном бандле Unfold.
3. В результате браузер игнорирует отсутствующие классы `text-gray-*` и применяет унаследованный от родительского контейнера цвет текста `text-font-default-light` (`--color-base-600`), представляющий собой ненасыщенный серый цвет (`oklch(44.6% .03 256.802)`).
4. На белом фоне (`bg-white`) серый текст имеет недостаточный коэффициент контрастности, что делает текст трудночитаемым для пользователей.

---

## 2. Требования к исправлению

1. **Гарантированная высокая контрастность текста:**
   - **Светлая тема (Light Mode):**
     - Основной текст сообщений, обязательств, фактов и сделок: глубокий темный цвет (`#0f172a` / `#111827` / `text-font-important-light` / `--color-base-900`) с коэффициентом контрастности > 7:1 на белом фоне (`#ffffff` / `bg-white`).
     - Второстепенные подписи и метаданные (лейблы, таймстемпы): четкий нейтральный серый (`#475569` / `text-font-default-light` / `--color-base-600`).
   - **Темная тема (Dark Mode):**
     - Основной текст: яркий светлый цвет (`#f8fafc` / `#f3f4f6` / `dark:text-font-important-dark` / `--color-base-100`).
     - Фон карточек: глубокий темный фон (`#0f172a` / `dark:bg-base-900` / `dark:bg-base-950`).
     - Границы: полупрозрачные или темные разделители (`#334155` / `dark:border-base-800`).
2. **Охват затронутых компонентов:**
   - `backend/api/admin.py` в классе `MessageProcessingTraceAdmin`:
     - **Этап 1 (Входные данные WhatsApp):** блок текста сообщения `whatsapp_content`, блок заголовков, метаданные и JSON payload.
     - **Этап 2 (Зависимые сообщения ранее):** карточки найденных сообщений Qdrant RAG, текст сообщений, автор, процент сходства, дата/время.
     - **Этап 3 (Данные из Bitrix24):** карточка сделки, сетка параметров (сумма, компания, поисковый запрос, защита от дублей), сводка контекста AI.
     - **Этап 4 (Итоговая запись):** сетка структурированных фактов AI, карточка созданного проекта, карточка обязательства SLA, финансовая запись.
   - `backend/templates/admin/waha_dashboard.html`:
     - Карточки статуса сессии, целевой группы WhatsApp, подключенного аккаунта, контейнер QR-кода.
3. **Отказоустойчивость стилей (Defense-in-Depth):**
   - Внедрить как семантические классы Unfold (`text-font-important-light`, `dark:text-font-important-dark`, `bg-base-100`, `dark:bg-base-900`, `border-base-200`, `dark:border-base-800`), так и целевые CSS-классы с fallback-переменными в едином блоке стилей для карточек трассировки:
     ```css
     .mazory-trace-content {
       color: #0f172a;
       background-color: #ffffff;
       border-color: #e2e8f0;
     }
     .dark .mazory-trace-content,
     [data-theme="dark"] .mazory-trace-content {
       color: #f8fafc;
       background-color: #0f172a;
       border-color: #334155;
     }
     ```
4. **Сквозная верификация Playwright E2E:**
   - Создать E2E-тест Playwright (`frontend/e2e/mazory-admin-contrast.spec.ts`), проверяющий:
     - Успешную авторизацию в админке под учетной записью администратора.
     - Открытие детальной карточки `MessageProcessingTrace` (`/admin/api/messageprocessingtrace/<id>/change/`).
     - Проверку вычисленных стилей (`window.getComputedStyle`) текста сообщений на контрастность (цвет текста темный в светлой теме, не прозрачный и не светло-серый).
     - Проверку рендеринга всех 4 этапов трассировки.

---

## 3. Критерии приемки

1. Текст исходного сообщения WhatsApp и всех текстовых блоков трассировки четко и контрастно читается на белом фоне в стандартном режиме и на темном фоне в темном режиме.
2. Проверки Django (`uv run --project backend python manage.py check` и `makemigrations --check`) завершаются с кодом 0.
3. E2E тесты Playwright завершаются успешно (зеленый статус).
4. Изменения проверены и задеплоены на удаленный контекст `mazory` с перезапуском сервисов.
